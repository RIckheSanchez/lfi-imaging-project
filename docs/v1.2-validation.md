on/off, and assert phase_converted=False. Each output keeps the original file_path,
target_type, z_indices and metadata, with complete Part 2 metadata nested under
part2_preprocessing. Defaults for these scans produce output.amplitude rather than
spatial_products.amplitude_corrected; the selected source and normalisation are
recorded in ui_preprocessing.

## Native packaged application

The arm64 app was rebuilt from the fresh environment. The spec includes the
Part 2 source import path and part2_preprocess/config/default.toml data resource.
Actual Cocoa startup loads chip, toggles preprocessing, and renders real Volume
and Isosurface OpenGL framebuffers without captured application errors. App size
is approximately 218 MiB. The local bundle is ad-hoc signed, not notarized.

Required screenshots under docs/screenshots/bundle-v12/:
- bundle-preprocessing-off.png: chip, preprocessing disabled.
- bundle-preprocessing-on.png: chip, preprocessing enabled, dimensionless label.
- bundle-volume.png: 3D with visible depth_mm calibration explanation.

Additional isosurface/framebuffer captures and bundle-report.json are included.
The reconstruction checkbox is hidden and its explanation is visible. No actual
Part 3 reconstructor or Vegetables calibration is registered in this release.

Long changed histogram labels are re-centered after text changes. Preprocessed
pixels are labelled Processed value rather than Raw value. All-missing channels
raise readable errors and clear the old image/histogram/colorbar; partially missing
values are omitted from ranges/histograms and drawn transparently. CSV retains nan.
Marching cubes excludes missing-sample stencils using a mask; its finite internal
buffer is never used as a fabricated measurement or rendered missing surface.

## Teammate issues observed but not modified

- Part 2's default TOML and vendor resources are not correctly supplied by a
  normal wheel. UI explicitly provides its TOML and packages it. The source main
  snapshot also lacks vendor/data_import/loader.py, so several shared-loader tests
  skip. preprocess_part1 uses from_upstream on the public Part 1 result instead.
- Part 2 io.py documentation says phase is always radians, but the public
  from_upstream path intentionally preserves unconfirmed raw codes. UI metadata
  and labels use actual phase_units and upstream phase_converted, not that prose.
- Default spatial correction is disabled for Chip/Mushroom/Marble. This is a
  configuration limitation, not a pipeline failure; full spatial_products are
  only selected when actually present.
- Part 1 optional real-data tests can count as passed after printing skip. Its
  sidecar parser does not cover all recorded Vegetables key spellings; no missing
  depth is guessed or defaulted in the UI.
- Part 3 handoff readers assume radians based on the handoff contract, without
  independent calibration evidence for arbitrary NPZs. No NPZ loader is enabled.
  The unmerged desktop reconstructor branch has not been imported or patched.

Physical pixel sizes, phase encodings and beam-focus depth provenance still need
team/Karl confirmation. 3D coordinates remain sensor/sample indices, not physical
Z spacing. See docs/backend-integration.md for future Loader registration and NPZ
schema/provenance checks instead of monkeypatching viewer.smart_load.
